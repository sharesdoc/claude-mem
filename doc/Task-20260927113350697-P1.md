# 按用户每次输入分轮，异步生成完整的观察记录

## 1. 任务状态

- 任务等级：P1
- 完成状态：待实现
- 测试状态：未测试
- 概要描述（大白话）：把一次用户输入到下一次用户输入之间发生的所有原始事件作为一轮，等这一轮结束后再异步生成观察记录；用户结束会话时也要补上最后一轮，同时不阻塞 Claude Code 的正常工作。
- 来源与依据：用户连续讨论结论；由 tsk 根据当前对话建档
- 所属计划项：无
- 关联需求：无

## 2. 需求描述

当前每次工具调用都可能触发一次观察内容生成，导致模型调用频率过高，而且单次观察缺少同一轮处理过程中的完整上下文。本任务把观察记录的触发单位从“单个工具调用”调整为“用户输入开启的一轮处理”。

用户明确要求：

1. 原始事件记录与 Claude Code 自身执行完全分开。原始事件必须持续记录，观察记录和摘要信息通过异步流程生成，不能让 Claude Code 停下来等待。
2. 用户输入定义为“用户输入事件”，一次用户输入开启一轮新的处理范围。
3. 用户输入事件之后，记录本轮的所有内部执行事件，包括工具调用和其他内部调用，不限制具体调用类型。
4. 用户再次输入时，先关闭并异步处理上一轮，再开始记录新的用户输入事件及其内部执行事件。
5. 用户直接结束会话时，关闭并异步处理最后一轮尚未生成观察记录的原始事件。
6. 第一次用户输入不需要处理上一轮；只有存在上一轮未处理内容时，新的用户输入才触发上一轮处理。
7. 同一轮原始事件过大时，按指定大小切分为多个异步处理切片；切片只描述处理范围，不改变原始事件记录。

本任务不要求 Claude Code 等待观察或摘要结果，也不要求删除原始事件。模型不可用时，异步处理可以延期，但原始事件不能丢失。

事件编号统一采用以下概念：

- 用户输入事件编号：以用户输入发生时间为基础，精确到毫秒，用来标识一轮处理。
- 内部执行事件编号：在用户输入事件范围内递增，用来标识工具调用或其他内部事件。
- 内部处理切片编号：仅当本轮内容超过指定大小时产生，用来标识本轮被切分后的处理批次。

## 3. 需求分析

一次用户输入到下一次用户输入之间，通常包含用户目标、工具调用、工具返回、文件修改、测试结果和最终响应。这些内容作为整体交给观察生成模型，比按单个工具调用生成更能反映完整处理过程。

处理边界必须在用户输入事件到达时固定：

- 当前轮事件持续写入原始事件存储。
- 新用户输入到达时，前一轮被标记为已关闭，并生成不可变的处理范围。
- 新用户输入及其后续内部事件进入下一轮，不能混入上一轮。
- 会话结束时，当前未关闭轮次被关闭并提交异步处理。
- 异步处理只读取已经关闭的轮次；新轮次继续写入不会影响正在处理的切片。

现有永久原始事件表和待处理队列可以作为基础。需要增加“轮次关闭”和“异步处理切片”的元数据，不能依靠扫描当前不断增长的事件集合来推断边界。

以下内容为实现所需的合理补全：

- 用户输入事件编号虽然使用毫秒时间作为主要组成部分，但必须增加唯一性保证，避免同一毫秒内重复编号。
- 内部执行事件编号必须在同一用户输入事件范围内单调递增，不能只使用事件到达时间排序。
- 切片必须保存起始和结束内部执行事件编号，保证可以准确重放处理范围。
- 同一会话的异步切片需要保持顺序，并且重复投递不能重复生成观察记录。
- 这些补全是为了保证并发、重试和进程重启时的时序一致性。

## 4. 设计方案

【最优解】采用“实时原始事件流、用户输入关闭轮次、异步切片处理”的方案。

### 事件层级

```text
会话
└── 用户输入事件 U-时间戳
    ├── 内部执行事件 U-1
    ├── 内部执行事件 U-2
    ├── 内部执行事件 U-3
    └── 内部处理切片 U-S1：事件 U-1 至 U-3
```

建议在原始事件及处理元数据中保存：

- 会话标识；
- 用户输入事件编号及毫秒时间；
- 内部执行事件编号；
- 事件类型和原始内容；
- 处理切片编号；
- 切片起始事件编号和结束事件编号；
- 轮次或切片状态，例如进行中、已关闭、处理中、已完成、失败待重试。

### 处理流程

1. 用户第一次输入时创建用户输入事件，开启轮次，不提交上一轮处理。
2. 每个内部调用事件只写入原始事件存储，并分配当前轮次内的递增编号，不触发模型调用。
3. 用户再次输入时，原子地关闭上一轮，计算该轮事件范围，并按大小创建一个或多个不可变切片，然后投递异步观察生成任务。
4. 新用户输入创建新的轮次，后续事件只归属于新轮次。
5. 会话结束时关闭最后一个开放轮次，并按同样规则生成异步切片。
6. 异步 Worker 按切片读取原始事件，生成观察记录；观察生成失败时保留切片和原始事件，按既有受限补偿规则重试。
7. 摘要生成如果依赖观察记录，应以已完成的观察切片为输入，并保持同一轮次和切片顺序。

### 大批量切片规则

切片只在轮次关闭后计算。优先按事件顺序连续切分，并记录每个切片的事件编号范围。大小限制可以按字符数、序列化字节数或估算 token 数定义，但必须使用稳定的配置值，不能因为新事件到达而改变已经关闭的切片。

切片失败或模型暂不可用时，只改变异步处理状态，不回写或删除原始事件。处理任务必须通过“轮次编号 + 切片编号”幂等，避免重试生成重复观察记录。

备选方案是继续按工具调用直接触发观察生成，再由后续摘要合并。这种方案改动较小，但无法解决高频模型调用和单个观察上下文不完整的问题，不采用。

## 5. 关联影响

- 原始事件接收链路：需要为用户输入、内部执行事件分配轮次和递增编号。
- 数据库：需要新增或扩展轮次、切片及处理状态字段，并建立唯一约束和查询索引。
- 异步队列：需要增加“关闭轮次后投递切片”的任务类型、幂等键、重试和顺序控制。
- 观察生成：输入从单个工具事件改为已关闭轮次的一个或多个切片。
- 摘要生成：需要识别观察切片的顺序和完成状态，不能读取仍在写入的开放轮次。
- 会话结束流程：必须保证最后一个开放轮次先关闭，再提交异步任务。
- 模型不可用处理：继续保留原始事件；只延期异步观察和摘要任务，不阻塞 Claude Code。
- 性能：模型调用次数会减少，但单次请求平均输入量会增加，需要控制切片大小和队列并发。
- 数据规模：原始事件永久保留，观察切片元数据也会增加数据库容量；本任务不新增原始事件清理策略。
- 测试与文档：需要同步更新事件模型、异步处理流程、配置说明和相关测试。

## 6. 测试方案

验收标准：

1. 第一次用户输入只创建轮次，不触发上一轮观察生成。
2. 同一轮内多个工具调用和内部事件都被记录，并且内部执行事件编号连续递增。
3. 第二次用户输入到达后，上一轮被关闭并异步投递；第二轮事件不会进入第一轮。
4. 会话结束时，最后一轮被关闭并异步投递，即使没有下一次用户输入也不会遗漏。
5. Claude Code 继续执行时，异步观察和摘要任务不会阻塞用户输入、工具调用或内部事件记录。
6. 轮次内容未超过大小限制时生成一个切片；超过限制时生成多个连续切片，切片边界不重叠、不遗漏。
7. 新事件在异步处理期间继续写入时，不会进入已经关闭的轮次或正在处理的切片。
8. 异步任务重复投递或失败重试时，不会重复生成同一个轮次切片的观察记录。
9. 模型不可用时，原始事件和已关闭切片仍然保留，模型恢复后可以按既定顺序补偿。
10. 会话重启、异常退出和正常退出后，已关闭轮次与最后开放轮次的状态均可恢复。

建议测试层级：

- 单元测试：编号生成、轮次关闭、切片边界、大小限制和幂等键。
- 数据库集成测试：事件写入、轮次状态、切片范围、唯一约束和重启恢复。
- 异步队列测试：投递、顺序、重试、模型不可用和重复任务。
- 端到端测试：用户输入 → 多个内部事件 → 下一次用户输入 → 会话结束的完整流程。
- 回归测试：现有原始事件永久保存、活跃会话补偿、观察生成和摘要生成流程。

## 7. 附加说明

- “内部处理切片编号”是处理批次标识，不是新的原始事件类型。
- 毫秒时间用于表达用户输入发生时间；唯一性和严格顺序由唯一后缀或数据库序列保证。
- 用户输入事件和内部执行事件的原始内容必须先持久化，再异步投递处理任务。
- 本任务只定义按用户输入分轮和异步切片处理的机制，不直接改变模型提示词的具体文字内容；提示词如何组织整轮事件属于实现阶段的技术细节。
