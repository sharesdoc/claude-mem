## 5. 建议处理(🟡 important)

### R-001 🟡 `file-context` 改 async 静默禁用"读前历史观察注入"
- **位置**:`plugin/hooks/hooks.json:62-74`(PreToolUse/Read → `hook claude-code file-context`,新增 `"async": true` @ L71)
- **事实依据**:
  - handler `src/cli/handlers/file-context.ts:174-177` 返回 `{ hookSpecificOutput: { hookEventName, additionalContext: timelines.join(...) } }`,L117 文案 "This file has prior observations — supplementary context follows." ⟶ 该 hook 的职责是**在 Read 前把该文件的历史观察注入给 Claude**(注入型,非纯记录型)。
  - Claude Code hook 契约(经 claude-code-guide 核实):PreToolUse hook 设 `async: true` = 后台 fire-and-forget、工具立即执行、hook stdout **被丢弃** ⟶ `additionalContext` 永不生效。
- **推理**:async 后,file-context 每次 Read 仍会跑,但其注入产物被 Claude Code 丢弃 ⟶ "读前记忆注入"(claude-mem 招牌能力之一)**静默失效**,用户不会看到任何报错。
- **影响**:核心功能悄然降级;且本次 commit message 将该 hook 的 async 描述为纯"fire-and-forget、彻底不阻断"收益,**未披露注入丢失**这一副作用,属未声明的行为变更。
- **修复建议**:三选一,建议②——
  1. **接受上游取舍**(非阻断优先):保留 async,但需在 commit/文档**明确声明** file-context 注入自此停用,并同步更新 `doc/upstream-cherry-pick-list.md` 与 README 的功能描述。
  2. **【推荐】保留注入、仅对该 hook 放弃 async**(分叉特化):去掉 `file-context` 的 `"async": true`,只让 `observation`(PostToolUse)与 `summarize`(Stop)保持 async。理由:这两个是纯记录/触发型,async 无损;file-context 是唯一注入型,其阻断风险已被 `timeout:60` + 我方 `bun-runner.js` 退出码归一化兜住,无需靠 async。
  3. 若既要非阻断又要注入:需改用同步 hook + handler 内部超时快速返回(工作量最大,非本轮范围)。
- **需补测试**:无自动化手段验证 hook 注入(依赖 Claude Code 运行时);至少补一条**人工验证步骤**——启用后 Read 一个有历史观察的文件,确认是否仍出现 "prior observations" 注入。
- **置信度**:高(handler 返回值 + 官方 hook 契约双证据)
- **处理建议**:合并前定夺;选②则回退单个 async 即可。
